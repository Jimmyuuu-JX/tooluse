# 动效打磨

目标：整体动效做到苹果那种细腻、丝滑的水准。

## 怎么找

不按部件去列，按「状态变化」去找。界面上任何东西的状态一变——出现、消失、移动、变大小、换内容、换图标、数值跳动、按下、悬停、加载、完成、出错——都问一句：这个变化用户看得懂吗？是突然跳过去的，还是有来有去、交代清楚了？大到页面切换，小到一个图标、一个数字、一个勾，都在范围里。

## 好动效的标准

- **解释发生了什么**：东西从哪来、到哪去、和什么有关，而不是装饰。
- **整个项目一套语言**：同一类变化用同一种曲线和节奏；项目里已有的统一起来，不要每处自己发明。
- **克制**：快、轻、不抢戏；用户反复做的操作要更快，宁可少动也不乱动。
- **跟手、可打断**：拖动和调整大小时直接跟手，动画进行中再次操作也能自然接上。
- **不付性能代价**：只动必要的东西（优先 `transform` 和 `opacity`），长内容里也要稳定满帧；交付前用浏览器的性能录制量过。
- **不引入新问题**：不抖、不闪、不重排、不溢出，尊重系统的「减少动态效果」（`prefers-reduced-motion`）。
- **各种环境都成立**：手机、窄窗口、宽屏、深浅色逐项看过。

## 两种用法

- **顺手对照**：加或改动画、过渡时，用上面的标准检查这次改动本身，沿用项目已有的曲线和时长，不借机扩大范围。
- **专项打磨**：用户要求把某个产品或区域的动效整体做好时，按下面的流程走。范围按用户说的；没说就是当前项目用户看得到的全部界面。

## 专项打磨流程

1. 先盘点项目里已有的动效：时长、曲线、写法。定一套少量的档位（几档时长、几条曲线），放进项目已有的样式变量或常量里。
2. 按状态变化逐个过界面，记下突然跳变、交代不清、各自发明、过度装饰的地方。需要第二视角时，另找一个独立的审查方当方案、文案、交互顾问。
3. 审完直接做：先统一已有的，再补缺的。
4. 修完亲手操作一遍，包括连续快速操作和动画中途再操作；量性能；切换各种尺寸、深浅色和「减少动态效果」。再请独立审查方复核这次改动。
5. 提交、合并、上线按所在仓库的规则和用户的授权进行，本 skill 不授予这些权限。
